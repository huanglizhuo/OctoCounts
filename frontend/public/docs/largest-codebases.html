How many lines of code? The largest codebases, counted

Counted by OctoCounts with tokei 14.0.0 over each repository's default branch at a pinned commit (test, docs, and generated-file exclusion rules enabled): the Linux kernel has 32,360,324 code lines, Firefox 24,586,522, LLVM 8,307,824, TensorFlow 5,130,571, Godot 4,120,690, Kubernetes 3,901,619, PostgreSQL 1,631,788, and git 1,148,625. These historical figures name the measured commit prefix and date. Repository links open live reports, which may show different counts.

How these numbers were measured

Every figure comes from OctoCounts' own counting pipeline: the repository's default branch is resolved to an exact commit, the source archive of that commit is downloaded (no git history), and the tree is counted with tokei 14.0.0. The published configuration excludes files matched by the test, docs, and generated-file rules; this does not prove that every remaining line is hand-written. Repository links open live reports, not preserved copies of these measurements. Download the published historical table as JSON. How many lines of code is the Linux kernel?

32,360,324 code lines at commit 4056b3c9d3c9 (October 14, 2026) — 42,580,025 total lines including comments and blanks, across 89,182 files in 50 languages, C at 60.8% of code. The kernel's master branch advances daily, so treat the number as "the kernel in mid-October 2026," not an eternal fact; the live report may show a later measurement. Cite this historical table for the figures above. It remains the largest public codebase most people can name, and the only one in this table where even the compressed source archive is a few hundred megabytes.

How many lines of code is Firefox?

24,586,522 code lines at commit 3934f7874da5 (October 14, 2026), across 140,115 files — the largest file count in this set — in 91 languages, the widest language mix here. C++ leads at 22.8% of code; comments are 19.9% of all lines, the highest comment share among the systems codebases measured. The full report shows why one-line comparisons of "Firefox vs Chromium" are treacherous: file counts and language mixes differ as much as line totals.

Which is the largest codebase ever?

There is no verified answer. "Largest" depends on what you count (code only, or comments and blanks? generated code? vendored dependencies?), and the biggest systems — automotive platforms, telecom switches, large SaaS monorepos — are not public. Among public GitHub repositories, the Linux kernel is the most-cited giant, and claims of "hundreds of millions of lines" for closed systems circulate without a reproducible methodology. For the largest repositories OctoCounts has actually measured, ranked and updated continuously, see the Hall of Monoliths.

Why do line counts for the same codebase differ between websites?

Four things to record when comparing counts:

  1. The tool. wc -l counts every line in every text file; cloc, tokei, and scc split code from comments and blanks, each with its own language database (the tokei vs cloc vs scc comparison covers the differences).
  2. The options. Including or excluding tests, docs, generated files, and vendor folders can swing totals by 20–50% — OctoCounts' pilot study measured exactly how much on react and vite.
  3. The commit. A default branch moves daily; a count without a commit SHA describes a moving target.
  4. The date. The measurement date records when the count was made; a fixed commit identifies the same tree regardless of measurement date.

So the citable form is: tool + version + options + commit + date. "32,360,324 code lines of torvalds/linux at 4056b3c9d3c9, tokei 14.0.0, tests/docs/generated excluded, counted 2026-10-14" states the known measurement context, although a full reproduction also requires the original effective rules; "Linux has 32 million lines" cannot.

Does more code mean a worse codebase?

No — and this dataset is the argument. PostgreSQL averages 395 code lines per file with 30.3% of all lines being comments: dense, heavily documented code. Kubernetes averages 260 code lines per file at 80.5% code. The linux kernel averages 363 code lines per file across 50 languages. Size is an input to planning, budgeting, and the honest sanity check (“is this really too big to audit before we depend on it?”) — not a verdict on engineering quality.
