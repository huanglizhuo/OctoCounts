## Design Context

### Users
Developers and engineers who want to quickly inspect the size and composition of a public GitHub repository — for due diligence, curiosity, or sharing. Used in short sessions (a few minutes), on desktop or mobile, often during a code review or technical conversation. The social sharing feature (PNG export) suggests the audience also wants to broadcast findings.

### Brand Personality
Precise, fast, unapologetic. The tool is a utility, not a product — it does one thing and reports the result. No fluff.

### Aesthetic Direction
CRT terminal aesthetic: dark backgrounds, monospaced type throughout, scan-line overlay, and two switchable modes (Matrix/Night and Paper/Day). The terminal metaphor is intentional, not lazy — OctoCounts is a command-line tool made web-accessible. The CRT flicker and scan-lines reinforce this. Anti-reference: generic SaaS dashboards with rounded cards, gradient text, and glassmorphism.

### Theme System
Two intentional modes:
- **matrix / night**: deep green-tinted dark, bright green accent — classic terminal
- **paper / day**: warm off-white, forest green accent — printed output / light reading

### Design Principles
1. **Utility over decoration** — every visual element earns its place by aiding comprehension or reinforcing the terminal metaphor
2. **Glows are functional, not decorative** — only status indicators (dot) and language color keys carry glow; text values do not
3. **Typography as data** — JetBrains Mono throughout is intentional for a code-counting tool; the monospace IS the brand
4. **Asymmetry signals hierarchy** — layouts vary intentionally (step cards 2fr/1.5fr/1fr, topbar left-heavy) to guide the eye
5. **Theme consistency** — Day and Night must preserve the same information hierarchy and interaction quality
