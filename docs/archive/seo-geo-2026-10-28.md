# SEO / GEO 增量优化 · 2026-10-28

本轮检查 OctoCounts 的现有预渲染、canonical、robots、结构化数据、Markdown、RSS 和 sitemap 链路，并修复确定性遗漏。本文记录发布前验证；按项目现有流程推送 `main` 触发 Cloudflare Pages 发布，实际结果以对应提交的部署检查和线上冒烟验证为准。这不是搜索排名或 AI 引用增长报告。

## 官方依据

- [Google：AI features and your website](https://developers.google.com/search/docs/appearance/ai-features)：AI 搜索仍依赖正常抓取、索引、可见正文和与正文一致的结构化数据，不要求额外的 AI 文件或特殊 Schema。保留项目已有 HTML / Markdown 和 llms 入口，没有为“GEO”增加重复内容或新依赖。
- [Google：Canonical URLs](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)：重复页面可用永久跳转统一到首选 URL，减少重复抓取，并保持 canonical 与 sitemap 一致。
- [Google：JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)：预渲染有利于不能执行 JavaScript 的抓取器；错误响应需正确表达状态，客户端不能把 canonical 改成另一页面。
- [Bing Webmaster Guidelines](https://www.bing.com/webmasters/help/bing-webmaster-guidelines-30fba23a)：搜索与 AI grounding 共用抓取、索引和内容清晰度基础；sitemap 的 lastmod 应反映真实变化，结构化数据应准确表达可见事实。
- [OpenAI crawler documentation](https://developers.openai.com/api/docs/bots)：OAI-SearchBot 的搜索用途与 GPTBot 的训练用途分开。线上 robots.txt 抽查可读，已有搜索抓取许可；本轮未调整训练许可或 Cloudflare 规则。

以上资料于 2026-10-28 查阅。仅获取公开 robots.txt 不代表真实爬虫 IP 已通过生产 WAF。

## 发现与修复

| 问题及证据 | 实现后的行为 | 验证方式 |
|---|---|---|
| 线上 `/home`、`/home-zh` 返回 200 首页副本；已有规则只处理 `.html` | 308 到 `/`、`/zh`；同时收口 `/index`，保留来源参数并处理旧语言参数 | 路由测试覆盖 EN / ZH 和 UTM 参数 |
| 线上 `/compare/React-Vs-Vue` 返回 200，与小写 canonical 重复 | 按已有比较 registry 跳转到标准 slug；Markdown 后缀和查询参数保留 | 大小写、URL 编码、`.md`、`?format=md` 回归 |
| `/stats` 的 HTTP 错误会输出可缓存的 200 空内容；网络或非 JSON 错误可能直接抛出 | 复用 8 秒上游超时，校验实际展示的数据；失败返回 503、no-store、Retry-After，HTML / Markdown 一致 | HTTP / 网络 / 超时异常、错误 JSON、坏行及合法零数据回归 |
| Trending 文件缺失、非 JSON 或坏数据会冒充空列表；RSS 还会用当前时间生成“更新日期” | HTML / Markdown / RSS 同步返回可重试 503；真实空快照仍为 200，RSS 使用真实采集时间 | 三种表示、日期和数据行校验回归 |
| Trending 的内部读取继承外部 HEAD / 条件请求，可能拿到空正文 | 内部固定无条件 GET，避免请求头污染数据读取 | HEAD、If-None-Match、If-Modified-Since 回归 |
| Trending 数据不可用时，sitemap 无法确定该页及静态分片的完整更新时间 | 保留独立可用的 sitemap URL 清单，省略未知 lastmod | 静态 sitemap 与 sitemap index 故障回归 |

改动集中在 `frontend/functions/[[path]].js` 和已有 SEO 测试；没有修改后端 API、公开数据格式或页面的正常交互。错误页不附加 noindex，避免把暂时故障变成主动移除索引的指令。正常页面正文没有改动，因此没有批量刷新内容日期。

## 验证结果

- TypeScript、Vite 和中英文首页预渲染构建通过。
- SEO 回归：115 / 115 通过。
- 单元测试：63 / 63 通过。
- Chromium 定向回归：6 / 6 通过，覆盖中英文首页、中文指南及 default / tree / commit 报告元数据。
- CSP、产品事实（55 个文件）、资源预算及 diff 空白检查通过。
- 使用当次线上 `/api/stats` 的真实响应及仓库当前 Trending 快照执行本地渲染，HTML / Markdown / RSS 均正常返回 200。
- 线上抽查还确认 robots.txt、静态 sitemap 可读，随机不存在的页面返回 404。Python 系统证书链读取失败后，改用正常验证 TLS 的 curl 完成检查；未关闭证书验证。

## 部署后检查与效果衡量

1. 发布前端后，复查 `/home`、`/home-zh` 和 `/compare/React-Vs-Vue` 的 308 及 Location，目标页面应正常返回 200；若仍为 200 副本，则本轮 canonical 修复未实际生效。
2. 确认 `/stats`、`/trending`、各 Markdown 表示和 RSS 的正常响应；通过预览环境模拟上游故障，确认 503 / no-store / Retry-After。无需为验证而中断生产后端。
3. 查看 Google Search Console 的重复页面和服务器错误趋势。持续 503 应作为可用性故障修复，不能把正确错误状态当作长期 SEO 策略。
4. 按 [现有测量规范](seo-geo-measurement.md) 对比发布前后等长 28 天窗口：GSC 展现/点击、Bing AI Performance 的引用/被引用页面、`ai_visit` 与 `analyze_completed`。点击归因不等于 AI 引用数量，前后变化也不能单独证明本轮改动的因果效果。

本轮未访问 GSC / Bing 私有后台，未测真实用户 Core Web Vitals，也未验证真实爬虫通过 WAF 的情况；这些数据保持未知。未运行后端测试和全部视觉 QA，因为本轮没有修改后端或界面布局。
