# SEO / GEO 多方向验证与修复 · 2026-11-01

本轮从八个方向做验证：线上抓取与索引、站内链接、结构化数据、JS 渲染后 DOM 与 SSR 的一致性、AI 入口（llms、Markdown 版本、AI 爬虫 UA）、内容事实、Lighthouse，以及 README 等项目内容。本文件只记录代码和内容修复及其验证，不代表已经部署、收录或排名变化。

| 方向 | 方法 | 结果 |

## 发现与修复

| 问题 | 修复后的行为 | 验证 |
|---|---|---|
| 1. 报告页（6,881 个可收录 URL）：Google 索引的是 JS 渲染后的 DOM，而 `createRoot()` 会丢弃边缘 SSR 输出。渲染后的页面没有可引用的摘要、规模分析、FAQ 和相关对比链接，只有不执行 JS 的爬虫能看到这些内容 | 摘要、规模分析和 FAQ 的文本生成函数移到共享模块 `functions/report-copy.js`，相关对比移到 `compare-registry.js`；客户端新增懒加载的 "About this report" 区块，逐字渲染同样的内容。SSR 输出与线上逐字一致。报告模板的 lastmod 改为 2026-11-01，让 Google 重新抓取并渲染 | 浏览器测试检查摘要、三条 FAQ 和对比链接；端到端渲染后的 DOM 已包含这些内容 |
| 2. `/recent`、`/popular`、`/hall-of-monoliths`、`/trending` 渲染后丢失 63–64 条轮换报告链接，所以修复孤立报告页的链接只存在于原始 HTML 中 | 边缘把同一批链接以 JSON 写进 `<head>`（不在 `#root` 内，不会被 React 清掉），客户端读取后渲染同一列表 | 渲染后的报告链接数（原始/渲染）为 98/98、100/100、99/99、79/79，修复前渲染后只有 36、36、36、15 |
| 3. `/compare` 渲染后丢失通往 101 个精选对比页的链接 | 客户端渲染同一份精选列表 | 浏览器测试检查链接数等于注册表条目数 |
| 4. 集合页链接到 404 页面：后端列表包含 575 个文件数低于 5 的仓库（这些报告页返回 404，也不进 sitemap），`/recent` 第一页就有 2 个 | 边缘和客户端的列表都跳过这些仓库；分页仍按 API 返回的原始条数判断是否有下一页 | 边缘测试和浏览器测试 |
| 5. 相似仓库：边缘要求至少 10,000 行代码，客户端没有这个门槛，所以渲染后的页面链接到只有约 3k 行代码的仓库 | 门槛改为共享常量，客户端使用同一门槛 | 构建与类型检查 |
| 6. FAQPage 与页面可见内容不一致：`/extension` 的 FAQ 结构化数据在渲染后的页面上看不到；`/badges` 结构化数据里的 3 个问题与页面上 5 个问题的措辞不同 | `/extension` 客户端渲染 FAQ（中英文）；`/badges` 的边缘 SSR 和结构化数据直接使用页面上的 FAQ 原文 | 测试要求结构化数据等于 `en.json` 中的 FAQ，中文条数一致 |
| 7. 徽章缓存说明过时：README 和 `/badges` 写的是"1 小时边缘缓存 + 24 小时 SWR，tag/commit 永久 immutable"，而后端从 10-31 起实际是分支徽章 `s-maxage=86400, stale-while-revalidate=3600`，tag/commit 徽章 `s-maxage=604800` | 文案改为实际行为（分支最长一天，tag/commit 最长一周） | 测试把文案和 `backend/src/badge.rs` 中的响应头绑定 |
| 8. 7 个页面的 SSR H1 带着标题里的 " \| OctoCounts" 后缀 | H1 去掉品牌后缀，`<title>` 保留 | 边缘测试 |
| 9. 集合页上游故障时，503 页把 `undefined` 写进 `#root`、robots 和 og:image | 改用已有的集合页故障模板 | 故障回归测试；逐个检查所有故障响应，都不再出现 `undefined` |
| 10. 指向 `/research` 的锚文本仍写 "pilot study, September 2026" 等旧说法，而该页现在的主体是 10 月 27 日的 10 仓库研究 | 改为 "10-repository study, October 2026" 和 "SLOC filtering study: 10 repositories"（只改导航锚文本，指南日期不变） | 构建；HTML 与 Markdown 同步修改 |
| 11. README 中 launch kit 行指向已下线页面；徽章缓存表过时 | 删除该行，更新缓存表 | 链接检查 |
| 12. 徽章预览和徽章墙的图片被固定成 180×20，SVG 比例变形（Lighthouse image-aspect-ratio） | CSS 只固定一个维度 | 截图检查 |

公开计数规则、后端数据和 API 都没有改动。`/badges`、`/extension`、`/compare` 和三个集合页的 manifest 日期改为 2026-11-01，因为渲染后的内容确实变了；集合页在 sitemap 中本来就不输出 lastmod。

## 需要你处理

- **Cloudflare JavaScript Detections**：每个 HTML 页面末尾都被注入一段加载 `/cdn-cgi/challenge-platform/scripts/jsd/main.js` 的内联脚本，站点 CSP 会拦截它。结果是控制台报错、Lighthouse 最佳实践扣分，检测本身也没有生效。建议在 Cloudflare 的 Security → Bots 设置中关闭 JavaScript detections，或者接受这个报错。不要用 hash 放行，因为脚本内容每次请求都不同。
- **Dataset 的 license**：145 个页面的 Dataset 缺少 `license`（Google 推荐字段）。用什么数据许可需要你决定，并且要和默认的 `ai-train=no` 内容信号保持一致。
- **部署后**：按 `docs/how-to-run-and-deploy.md` 清除 `octo-html` 缓存，让已缓存的报告页和集合页用上新模板；按 [索引操作说明](seo-index-runbook.md) 重新提交 sitemap。然后在 GSC 用"网址检查 → 查看已抓取的网页"确认渲染后的 HTML 包含 "About this report"。
- **观察指标**：报告页组中"已抓取 - 尚未编入索引"的数量，以及 Bing AI Performance 和 AI Overviews 引用的页面。继续按 [测量规范](seo-geo-measurement.md) 对比等长周期的数据，不能从代码改动推断排名变化的原因。
