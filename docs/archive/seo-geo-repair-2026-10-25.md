## 第二轮发现并补齐的遗漏

1. **ref 识别与缓存链路**：纯十六进制分支被误判为 SHA；同一 commit 的第二个 ref 命中缓存或合并到同一作业后没有 SEO 记录。新增显式类型和独立映射，不重复计数或改写原报告；覆盖改名、映射指向尚无报告的新 SHA、映射写入失败等路径。
2. **页面身份漂移**：显式 ref 的 SSR canonical、Markdown 和 Dataset 指向默认报告；客户端加载后又把根页/commit 改成 tree。现统一保留当前路由语义，重新分析后同步 Markdown alternate；拒绝在 commit URL 下发布不同 SHA。`.html` 结尾的合法 GitHub 分支也不再被静态文档重定向截断。
3. **故障分支遗漏**：比较 sitemap 在故障时列出全部未确认 URL；报告上游非 JSON 会抛异常；部分数组内的坏记录、残缺计数规则未校验。现返回可重试的 503，而不是错误的成功内容或未处理异常。
4. **仍在发布的错误文案**：缓存立即命中、同 commit 必然复现、历史文章不存在的 pinned report、错误注释比例排名、无依据工具比较，以及隐私文字与可选登录的冲突。同步修正文案、HTML/MD 和隐藏 FAQ Schema，扩展事实检查。
5. **数据元信息**：移除无依据 Dataset MIT 标记；研究文章编辑日期与未重跑的数据集日期分开，研究 HTML/MD 同步披露原始规则记录的局限。
6. **验证与部署门禁**：修复数据库连接失败仍显示测试通过；Nginx `/index.html` 恢复继承全局安全头；预算检查按 manifest 标识识别导出器，补上漏检的 html-to-image，并加入负例自检。
7. **运维说明漂移**：部署文档仍要求 crawler UA 收到 Markdown，与当前 HTML 一致性策略矛盾。已改正，并明确历史 Cloudflare 观测不能当作本次线上验证。

在本次检查的仓库实现及测试范围内，未再发现未处理的确定性遗漏；下列线上和数据边界仍然保留，不能据此承诺网站不存在任何潜在问题。

## 发布与后续验证边界

- 后端先于对应前端发布：ref 修复依赖新的 SEO API 和 `refKind` 参数。现有启动迁移会创建 `repository_refs`，部署账号需要原有迁移所需的 DDL 权限。仅部署前端不能修正旧后端行为。
- 历史上未记录的同 SHA ref 别名无法从单个报告重建；下一次正常解析该 ref（即使分析命中缓存）会补映射，不伪造历史数据。
- 生产前端必须继续使用 Cloudflare Pages + Functions。本轮 Nginx 镜像明确为 noindex 的本地预览，不能直接替代生产 SEO 服务。
- sitemap 已取消总量截断，但目前仍一次读取报告清单；日后规模明显扩大时，按真实响应时延/内存证据再改为后端分页。
- 静态历史 JSON 是已公开数字的转录，缺失的原始 ID/完整规则没有被补造。新增研究及数据许可需要真实采样和权利依据。
- 部署后确认 WAF/机器人规则、HTML/Markdown/503/ETag 实际响应、统计事件入库，再读取等长时间窗口的 GSC/Bing/AI 引用数据。当前没有排名、引用率或转化提升的实证结论。
